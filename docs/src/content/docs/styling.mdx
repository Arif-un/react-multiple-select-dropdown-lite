## CSS variables

The defaults live on `.msl-vars`, the wrapper of every dropdown. Override them on `.msl-vars` for all dropdowns, or add your own class for one. Keep `.msl-vars` in the selector: a lone class of yours ties with the defaults, so it only wins when its CSS loads later.

## The open menu

The open menu is one box: the input box, `.msl.msl-active` (`.msl-active-up` opening upward), with the options attached. It is a popover over the dropdown, in the top layer, so `overflow: hidden` parents, stacking contexts and z-indexes don't clip or cover it, in a modal `<dialog>` too. It stays in place in the DOM, so your CSS reaches it through its ancestors and it inherits the text color, font and direction there. The dropdown keeps the input box's height. The menu follows the dropdown as the page scrolls, and lines up, scaled as the dropdown is, in a transformed dialog or a scaled part of the page. It is as wide as the dropdown and clips the options: to widen the menu, widen the open box (`.msl-active { min-width: 400px }`).

## Class names

State classes:

| Class                          | On      | When                                  |
| ------------------------------ | ------- | ------------------------------------- |
| `msl-disabled`                 | wrapper | `disabled`                            |
| `msl-limit-reached`            | wrapper | `limit` is reached                    |
| `msl-active` / `msl-active-up` | `.msl`  | menu is open, below / above the input |
| `msl-option-active`            | option  | selected                              |
| `msl-option-focused`           | option  | highlighted by the keyboard           |
| `msl-option-disable`           | option  | disabled                              |

Parts: `msl-wrp` (wrapper), `msl` (input box, and the open menu), `msl-chip`, `msl-chip-delete`, `msl-single-value`, `msl-input`, `msl-search` (the search field's box with `searchInMenu`), `msl-clear-btn`, `msl-arrow-btn`, `msl-options` (menu), `msl-option`, `msl-grp` (a group), `msl-grp-title`, `msl-grp-body` (a collapsible group's childs), `msl-submenu` (a submenu's popover).

A submenu shows in the top layer. The stylesheet places it with [CSS anchor positioning](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_anchor_positioning): beside its title, on the other side or above where there is no room, and over its title where neither side has room. Its title is its `position-anchor`, so your own `.msl-submenu` rules can place it elsewhere with `anchor()` or `position-area`. Open titles and collapsible group titles have `aria-expanded`; the stylesheet draws their chevrons as `::after`.

A single option can carry its own `classes` and `style`. To add classes to every part, Tailwind utilities for example, use the `classNames` prop: see [Tailwind](../tailwind/).

The component's inline styles are behavior, not looks: `display: contents` on the chip wrapper, which keeps that box out of the layout with or without the stylesheet, and, while the menu is open, the dropdown's `min-height` (the open box left the flow) and the popover's `position`, coordinates, width and scale, and a reset of the browser's popover look (`inset`, `margin`, `padding`, `border`, `background`, `color: inherit`, `overflow`), on the unstyled `<div>` around `.msl`, and, on an open submenu and its title, the `position-anchor` and `anchor-name` that tie them together, and, on a closed submenu's copy, the position it had. Everything else is in the stylesheet: without it the markup is unstyled, and plain CSS overrides any of its rules.

## Animations

Animate opening and closing with CSS, or with Tailwind's variants. The component sets no durations.

**Opening** needs nothing from the component. The options, a submenu and the rows of an expanding group are new elements, so `@starting-style` (Tailwind's `starting:`) or a keyframe animation brings them in. State changes transition as any CSS does: `aria-expanded`, `aria-selected`, `data-focused`, `data-open`.

**Closing** is where the component helps. Whatever closes stays until the CSS animations and transitions that its `data-closing` starts have ended:

| Closing                      | Marked                                                                   |
| ---------------------------- | ------------------------------------------------------------------------ |
| the menu                     | `.msl[data-closing]`, the open box, still `.msl-active` and `data-open`  |
| a submenu                    | a copy of its `.msl-submenu`, with `data-closing`, where the submenu was |
| a collapsible group's childs | a copy of its `.msl-grp-body`, with `data-closing`, where it was         |

- Without exit CSS, things close at once, as they always have. Transitions already running when it closes, such as an option's hover background, don't hold it, and neither does an infinite animation.
- A closing menu and the copies are inert: no clicks, out of the accessibility tree. Focus leaves the menu as it starts to close. `onMenuClose` fires then too, and the combobox reports itself collapsed.
- Opening the menu again before it has gone brings the same menu back, mid animation. A submenu or group that opens again replaces its copy.
- A keyframe exit animation needs `forwards`, so its end state holds until the element goes.
- Heights animate through a grid row from `0fr` to `1fr`, as below. The open box: `.msl` is a grid, the options its second row. Give the control's row `max-content`: an `auto` row would take the space a part `fr` row leaves. A collapsible group: `.msl-grp-body` holds one `<div>` for this. Make the body a grid with one `1fr` row, `0fr` in `@starting-style` and with `data-closing`, and give the `<div>` `overflow: hidden; min-height: 0`.
