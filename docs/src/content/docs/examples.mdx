## Groups

Groups have `type: 'group'`, a `title` and `childs`, and can nest. Options themselves can't have `type: 'group'` or `type: 'submenu'`. `emptyDataLabel` shows when a group has no options. With `collapsible: true`, a click on the title (or Enter) shows and hides the group's options; `collapsed: true` starts it closed. Search looks inside groups, closed ones too. `header` and `footer` go first and last in a group's rows, a submenu's popover or a collapsible group's body: text, not options, so the keyboard passes them and they have no role (controls go in [the menu's header and footer](#menu-header-and-footer)). Style them with `.msl-grp-header` and `.msl-grp-footer`.

<Preview code={groupsCode} title='Groups.tsx'>
  <Groups client:visible />
</Preview>

## Submenus

With `type: 'submenu'`, the title is a row that opens its `childs` in a popover beside the menu: on a pause over it, a click, Enter or Arrow Right. With the highlight in it, Arrow Left or Escape close it again. Submenus nest to any depth and can hold groups. Search lists their options flat.

## Group titles

`renderGroupTitle` renders the title rows of groups and submenus from `{ group, title, total, selected, open, icon }`: `total` counts the options in it, nested ones too, and `selected` those picked. `icon` is the expand icon, for you to place or leave out.

<Preview code={groupTitlesCode} title='GroupTitles.tsx'>
  <GroupTitles client:visible />
</Preview>

For an icon of your own, leave `icon` out and pick one from `open`. Push it to the end yourself: the stylesheet's auto margin is on `.msl-expand-icn` only. A submenu is `open` while its popover shows, so check `group.type` to keep its icon pointing right:

```jsx
renderGroupTitle={({ title, total, selected, open, group }) => (
  <>
    {title}
    <span>{selected}/{total}</span>
    {open && group.type !== 'submenu' ? (
      <ChevronDown aria-hidden className='ms-auto' />
    ) : (
      <ChevronRight aria-hidden className='ms-auto' />
    )}
  </>
)}
```

The stylesheet doesn't turn or mirror your icon, so it is up to you right to left.

A group or a submenu carries your own fields, typed, for `renderGroupTitle` to read back, and its own `classes` and `style`, as an option does. They go on its title row; the rest of it is reachable from there: `.msl-grp:has(> .vip)` the group's box, `.vip + .msl-grp-body` a collapsible group's rows, `.vip + .msl-submenu` a submenu's popover.

```jsx
const options = [
  { type: 'submenu', title: 'Team', icon: <UsersIcon />, classes: 'vip', childs: team },
  { type: 'group', title: 'Archive', style: { opacity: 0.6 }, collapsible: true, childs: old }
]

<MultiSelect
  options={options}
  renderGroupTitle={({ group, title, icon }) => (
    <>
      {group.icon}
      {title}
      {icon}
    </>
  )}
/>
```

## Creatable values

With `customValue`, typing text that matches no option offers **Create "..."**. Enter or comma adds it; created values are listed under **Custom Values**.

<Preview code={creatableCode} title='Creatable.tsx'>
  <Creatable client:visible />
</Preview>

`canCreate` says which text can be created: without it, no Create row, and Enter or comma creates nothing. `onCreate` makes the value: an option of your shape, named by your getters, or a value string, both listed under Custom Values until your `options` have them. `false` or nothing creates nothing, and the text stays. A promise, from a request say, shows `loadingLabel` in the Create row meanwhile (`aria-busy`, disabled, one call), then selects what it resolves to; a rejection shows `errorLabel` there (`data-error`), and a click creates again.

<Preview code={createAsyncCode} title='CreateAsync.tsx'>
  <CreateAsync client:visible />
</Preview>

Emails only here, and the pretend server fails for an address at `fail.com`. Paste `ada@example.com, new@example.com, x` to pick, create and leave each part.

In multi select, pasting text with commas, tabs or newlines picks each part: the option whose label text or value it is, in any case, else with `customValue` one it creates, through `canCreate` and `onCreate`. Up to `limit`, in one `onChange`. What doesn't go in goes in the search field at the caret, the text there kept.

## Controlled menu and search

`open` makes the menu yours: it shows exactly while `open` is true, and the dropdown's own opens and closes (a click, a key, Escape, a click outside, a pick with `closeOnSelect`) call `onMenuOpen` and `onMenuClose` for you to set it, or not. Opened from outside, as by a button of yours, focus stays where it is.

`search` makes the search text yours. `onSearchChange(text, reason)` tells each change: `'input'` as typed or pasted, `'pick'` as a pick clears it, `'close'` as the menu closes. Filtering, `onSearch` and `loadOptions` follow the text the field shows, so ignoring `'pick'` keeps the search after a pick:

## Fixed values

`fixed: true` on an option keeps it once selected: its chip has no delete button, and Backspace, the clear button and the menu leave it. In single select it locks the value. ## Select all

`selectAll` adds a first row that selects every enabled option the menu lists: a search's results only, those loaded so far, those in closed groups and submenus too, up to `limit`. Once none is left to pick, it has `aria-selected` and deselects them, `fixed` ones aside. The menu stays open, and the row hides while there is nothing to select. Multi select only; style it with `.msl-select-all`.

`toggle` in [`renderGroupTitle`](#group-titles) does it for one group, its nested and loaded options too. Put a checkbox in a plain group's title only: a collapsible group's or a submenu's title is an option, which screen readers read as text, so the example shows a count there. `total` counts disabled options too, so a group with one never shows checked. Each is one `onChange`.

## Custom labels

`getLabel(option)` renders each option, chip and single value. Return any JSX. Search matches what `getLabel` returns when it is text, else the option's `label`.

<Preview code={jsxLabelsCode} title='JsxLabels.tsx'>
  <JsxLabels client:visible />
</Preview>

Its second argument tells where the label shows: `{ context, search, selected }`. `context` is `'menu'` for an option's row and `'value'` for a chip or the single value, `search` is the search text for menu rows (`''` for values), and `selected` whether the option is picked. Below, the match in `<mark>` and a checkmark on the selected rows, plain text in the chips:

<Preview code={labelMetaCode} title='LabelMeta.tsx'>
  <LabelMeta client:visible />
</Preview>

Search reads the label's text for no search (`{ context: 'menu', search: '', selected: false }`), so the highlight never changes what matches. The tooltip reads the row's label text, else the option's `label`.

## Hide selected options

`hideSelected` takes picked options out of the menu and its search results. A group, a collapsible group or a submenu with no option left goes too, title and all; nothing left shows `emptyDataLabel`, or `selectAll`'s row, selected, which deselects them. Enter moves the highlight on to the next option, so the keyboard picks one after another. `renderGroupTitle`'s `total` and `selected` still count the hidden options.
